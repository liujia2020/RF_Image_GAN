# 02 — 数据管线详解

> 本文档按"来源→目的→方法→流程→踩坑"统一模板组织，确保每一步可追溯、可复现。

## 总览图

```
.mat 原始采集 → 时延对齐+DAS重建 → Patch裁剪 → HDF5存储 → Python维度重排 → fp16 Cache → 训练读取
    ①               ②                 ③           ④            ⑤              ⑥            ⑦
```

| 步骤 | 输入 | 输出 | 执行环境 |
|------|------|------|----------|
| ① 原始采集 | Verasonics | `.mat` 文件 (312个) | MATLAB |
| ② 重建+裁剪 | `.mat` | `.h5` 文件 (1500个) | MATLAB |
| ③ HDF5 存储 | 重建 volume | H5 内部结构 [3,128,32,32,64] | MATLAB 写入 |
| ④ 维度重排 | H5 MATLAB 序 | `[1536,64,32,32]` PyTorch 序 | Python |
| ⑤ fp16 Cache | 1500×H5 | 6个连续 .dat + meta.npz (282G) | Python |
| ⑥ 训练读取 | .dat memmap | DataLoader batch | Python |

## ① 原始 RF 数据采集

**来源**：Verasonics Vantage 256 多通道超声平台

**目的**：采集 312 个个体的 75 角度平面波 RF 数据，覆盖三类组织

**方法**：RC6gV RCA 探头（128+128 阵元），正交平面波（OPW）发射模式。
RC 模式（行发列收）+ CR 模式（列发行收）互补叠加，使 PSF 各向同性。

**流程**：
1. 探头置于组织表面，依次发射 75 个倾斜平面波（-16°~+16° 均匀分布）
2. 正交阵列接收背散射 RF 信号，采样率 25 MHz
3. 保存为 `.mat` 文件，每个文件包含一次完整采集的所有通道数据

**关键参数**：

| 参数 | 数值 | 
|------|------|
| 探头 | RC6gV (Vermon)，128+128 阵元 |
| 阵元间距 | 0.2 mm |
| 阵列边长 | 25.6 mm |
| 中心频率 | 6 MHz |
| 采样率 | 25 MHz |
| 声速 | 1540 m/s |
| 采集角度数 | 75 个 (-16°~+16°) |

> ⚠️ **踩坑**：`01_source_mat` 中的 Phantom .mat 最初被遗漏，仅统计了 Carotid(102)+Muscle(100)=202 个。
> 后补全 Phantom(100) → 共 302 个。原始数据盘点是项目重启的第一道关卡，必须全量核对。

## ② 时延对齐 + DAS 重建 → Patch 裁剪

**来源**：`01_source_mat` 中的 312 个 `.mat` 原始 RF 文件

**目的**：从原始 RF 全容积中抽取 1500 个 64×32×32 的 patch，每个 patch 包含：
- input（3 角度 RF 张量）
- label（33 角度 DAS，高质量目标）
- baseline（3 角度 DAS，低质量参考）

**方法**：

- **时延对齐**：逐体素计算传播时间（发射+接收），将 RF 信号按时间延迟对齐到成像网格
- **DAS 重建**：对齐后的信号求复数包络，在角度维度上相干叠加
- **Patch 裁剪**：从全容积 [1024,128,128] 上随机抽取连续子块

**角度选择逻辑**：

| | 输入角度 | 目标角度 |
|------|----------|----------|
| 数量 | 3 个 | 33 个 |
| 值 | 3°, 38°, 73° | 1°~75° 均匀 |
| 物理含义 | 帧率高、画质差 | 帧率低、画质好 |

**流程**：
1. 对每个 `.mat` 文件，在全容积 [1024,128,128] 上随机抽取 5 个 64×32×32 的 patch 位置
2. 对每个 patch 区域做时延对齐（只算 patch 范围的体素，不先算全卷）
3. 对对齐后的 RF 分别做 3 角度 DAS（→ baseline）和 33 角度 DAS（→ label）
4. 保存为单个 HDF5 文件

**文件级划分**：
- 300 个 RF 文件 × 5 patch = 1500 个 HDF5
- 每类 100 个 RF：train 70 / val 15 / test 15（文件级，不是 patch 级）
- 同一 RF 文件的所有 patch 在同一个 split 里 → 防止数据泄漏

> ⚠️ **踩坑**：随机种子固定在 `gen_opts.random_seed = 640032`。
> 若更换种子，patch 位置会变，之前所有 golden values 和 Phase 0 诊断作废。
> 不要随意重跑 MATLAB 生成脚本。

## ③ HDF5 文件内部结构

**来源**：MATLAB `make_RF_learning_sample_v2` 写入

**目的**：以自描述的层次结构存储单个训练样本，包含 input/label/baseline/meta 四组数据

**方法**：HDF5 格式，每组数据以 Dataset 形式存储在 `/sample_000001/` 下

**流程**（MATLAB 写入 → Python 读取）：

### input 组（RF 张量，4 个 5D 数组）

```
F_RC_real  [3角度, 128通道, 32(Y), 32(X), 64(Z)]
F_RC_imag  [3, 128, 32, 32, 64]
F_CR_real  [3, 128, 32, 32, 64]
F_CR_imag  [3, 128, 32, 32, 64]
```

- **RC**：正向传输（Row→Column）
- **CR**：反向传输（Column→Row）
- **实部+虚部**：复数信号的 IQ 分解

### label 组（目标 DAS，2 个 3D 数组用于训练 + 4 个辅助）

```
DAS_target_avg_real  [32(Y), 32(X), 64(Z)]  ← 训练用
DAS_target_avg_imag  [32(Y), 32(X), 64(Z)]  ← 训练用
DAS_target_sum_real  [32, 32, 64]  (备用)
DAS_target_sum_imag  [32, 32, 64]  (备用)
DAS_target_avg_abs   [32, 32, 64]  (备用)
DAS_target_sum_abs   [32, 32, 64]  (备用)
```

- **avg vs sum**：avg（平均加权）各角度贡献均等、散斑更均匀；sum 信噪比高但纹理不自然
- 训练只用 avg 的实部+虚部

### baseline 组（低质量参考，同 label 结构）

```
DAS_input_avg_real   [32, 32, 64]
DAS_input_avg_imag   [32, 32, 64]
... (sum/abs 同 label)
```

3 角度 DAS 重建结果，作为"不做深度学习的基线"。训练时用作：
- 判别器的条件输入
- 生成器的辅助起点

### meta 组（空间索引）

```
z_idx  [1, 64]     patch 在原始 volume 中的 Z 轴坐标（MATLAB 1-based）
x_idx  [1, 32]     X 轴坐标
y_idx  [1, 32]     Y 轴坐标
z_axis_mm / x_axis_mm / y_axis_mm  物理坐标
patch_size  [1,3]  = [64, 32, 32]
```

> ⚠️ **踩坑**：MATLAB 索引是 1-based，Python 切片前必须减 1。
> 曾因为索引差 1 导致拼接错位，排查了几个小时。

## ④ Python 维度重排

**来源**：HDF5 文件（MATLAB 维度顺序 `[角度,通道,Y,X,Z]`）

**目的**：转换为 PyTorch 需要的维度顺序 `[通道合并, Z, X, Y]`，
即 input=[1536,64,32,32]、label/baseline=[2,64,32,32]

**方法**：`rf_learning_dataset.py` 中的 `_read_rf_tensor()` 和 `_read_volume()`，
纯 numpy transpose + reshape，无数据损失

**流程**：

**input 重排**：
```
读 HDF5: F_RC_real [3,128,32,32,64]
↓ _read_rf_tensor(): transpose → [64,32,32,128,3]
↓ stack 4 分量: [64,32,32,128,3,4]
↓ transpose → [128,3,4,64,32,32]
↓ reshape → [1536,64,32,32]
   (1536 = 128通道 × 3角度 × 4分量)
```

**label/baseline 重排**：
```
读 HDF5: DAS_target_avg_real [32,32,64]
↓ _read_volume(): transpose → [64,32,32]
↓ stack 实部+虚部 → [2,64,32,32]
```

**归一化逻辑**：
```python
if normalize:                           # normalize=True
    scale = max(abs(label)) + 1e-8      # scale 由 label 最大绝对值决定
    input    = input / scale            # 三个字段除以同一个 scale
    label    = label / scale
    baseline = baseline / scale
else:                                   # normalize=False（旧版默认）
    scale = 1.0                         # 不缩放
```

> ⚠️ **踩坑**：旧版默认 `normalize=False`（scale=1.0），这个决定直接导致了后面的 fp16 溢出问题。
> 详见第五步。

## ⑤ Memmap Cache 生成

**来源**：`02_h5_patches` 中的 1500 个 HDF5 文件（第四步输出）

**目的**：将散落的 1500 个 HDF5 合并为 6 个连续二进制 memmap 文件（每个 split 4 个 .dat），
消除逐文件随机 I/O 瓶颈，float32→float16 压缩一半存储。训练时每个 epoch 不再逐个打开 H5。

**方法**：`rf_cache_builder.py`，逐样本 `RFLearningDataset.__getitem__()` 
→ `astype(float16)` → 写入 memmap。只做格式转换，不改变数值（除 fp16 精度损失外）。

**流程**：
```python
# 修正版（2026-06-07）
for idx in range(n_samples):
    item = dataset[idx]                                          # normalize=True
    s = item["scale"]                                             # scale = max(|label|)
    input_mm[idx]    = (item["input"]    / s).astype(np.float16)
    label_mm[idx]    = (item["label"]    / s).astype(np.float16)  # max → 1.0
    baseline_mm[idx] = (item["baseline"] / s).astype(np.float16)  # max → ~6.1
    scale_mm[idx]    = s.float()
```

**最终 Cache 结构**：
```
03_fp16_cache/
  train/
    input.dat       [1050, 1536, 64, 32, 32]  float16  (~197 GB)
    label.dat       [1050, 2, 64, 32, 32]     float16  (~8.6 GB)
    baseline.dat    [1050, 2, 64, 32, 32]     float16  (~8.6 GB)
    scale.dat       [1050]                     float32  (~4 KB)
    meta.npz        paths, categories, z/x/y indices, shapes, normalize flag
  val/     (225 samples, 同结构)
  test/    (225 samples, 同结构)
总大小: ~282 GB (fp16)
```

> ⚠️ **踩坑 1 — fp16 溢出（2026-06-07 诊断）**
> 旧版直接 `.astype(np.float16)`，scale 只存入 scale.dat 但从未用于缩放数据。
> 全量 1500 扫描结果：input 安全（max 19,332），label 192/1500 溢出（max 256,494），
> baseline 377/1500 溢出（max 304,138）。溢出集中在 carotid/muscle 真实组织，
> phantom baseline 也有 9 个样本溢出（被抽样漏检，全量才抓出）。
> **修复**：`normalize=True`，scale=max(|label|)，三字段同除 scale 后再转 fp16。
> 验证：label max→1.0，baseline max→6.1，全量零溢出。

> ⚠️ **踩坑 2 — reader 还原后不能返回 fp16（2026-06-07）**
> Reader 端乘回 scale 后值可达 30 万，远超 fp16 上限。若再转 fp16 会重新溢出。
> **修复**：归一化 cache 的 reader 强制返回 fp32，忽略 `return_fp16=True`。

> ⚠️ **踩坑 3 — scale 对称性是命门**
> 生成端除 scale、reader 端乘 scale，两端必须严格配对。任一端错或不对称，
> 训练数据静默错且不报错。改生产代码时必须同步改两端、交叉验证。

> ⚠️ **踩坑 4 — 盘满导致写入静默失败（旧 cache 根因）**
> 旧 cache 在 NTFS 盘满 100% 时生成。memmap 文件大小预分配正确（282G 精确匹配），
> 但实际数据未落盘，留下 NaN/全零垃圾。新 cache 必须写在 ext4 且有充足空间。

> ⚠️ **踩坑 5 — 验证必须全量，禁止抽样**
> 旧 cache 的 `verify_split_cache` 只随机抽 20 个样本，漏掉了坏的。
> fp16 溢出诊断也因抽样 150/1500 漏了 phantom 的 9 个 baseline 溢出样本。
> **铁律：关键验证一律全量。**

## ⑥ 训练时读取

**来源**：`03_fp16_cache` 中的 .dat memmap 文件

**目的**：以最高 I/O 效率将训练数据喂给 DataLoader，避免逐 H5 打开的瓶颈

**方法**：`rf_cached_dataset.py` 使用 numpy memmap（操作系统 page cache 自动缓存热数据）

**流程**：
```python
# 打开时不加载数据——只建立虚拟地址映射
self.input = np.memmap("input.dat", dtype=np.float16, mode="r",
                        shape=[1050, 1536, 64, 32, 32])

# 读取时：
# 1. fp16 memmap → np.float32
# 2. 乘 scale 还原真实物理值
# 3. → torch.float32
data = torch.from_numpy(np.array(self.input[idx], dtype=np.float32))
data = data * self.scale[idx]  # 还原
```

**归一化 cache 的强制约束**：
```
fp16 memmap → 转 float32 → 乘 scale → 返回 float32
```
即使 `return_fp16=True`，归一化 cache 也强制返回 float32（因为还原后值 >65504）。

**fp16 vs fp32 训练策略**：
- `return_fp16=False`（默认）：硬盘读 fp16 → 还原 → float32 → GPU
- Page cache 效果：epoch 1 较慢，epoch 2+ 热数据全在内存，接近内存速度

---


> ⚠️ **踩坑 6 — AMP fp16 导致 struct loss 溢出（2026-06-07 smoke 发现）**
> 数据还原后是真实物理幅值（label 可达 25 万，pred 可达 7.7 万）。
> struct loss 计算包络  时，7.7万² ≈ 5.9×10⁹，远超 fp16 上限 65,504。
> AMP（自动混合精度）把部分运算降到 fp16 → 平方步骤立刻溢出成 inf → G_struct=inf。
> **修复**：。RTX 5060 显存充裕（smoke 仅用 2.78GB），全 fp32 训练完全可行。
> 单变量对比确认：AMP on → 第1步炸；AMP off → 2步全通，零 inf。
