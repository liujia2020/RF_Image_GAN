# 验证规则与项目纪律

> 最后更新: 2026-06-13。

## 运行组织

每个正式运行按三个阶段组织：

```text
experiments/<track>/runs/<YYYY-MM-DD_short_name>/
├── 01_config/          训练前配置 (README / config.yaml / manifest)
├── 02_train/           训练产物 (checkpoints / probes / logs / loss)
└── 03_validate/        验证结果 (figures / metrics / verdict)
```

每次实验应能回答：

- 在测试什么想法？
- 哪个模块/改动实现了它？
- 唯一的自变量是什么？
- 运行了什么 smoke test？
- 用了什么训练配置？
- 训练中有什么探针图像/指标可供检查？
- 最终汇总在哪？

## Smoke Test

Smoke test 只回答：

- 代码能跑吗？
- 有 NaN 吗？
- 有 OOM 吗？
- loss 能正常计算吗？

Smoke test 永远不能证明质量。

**小样本自检（全量训练前）**：取一 batch 打印 pred/gt 形状 [1,64,32,32]、值域 [0,1]；SSIM3D 与 L1 能算、无 NaN/Inf；loss 有限。通过再跑满 50 epoch。

## 大规模数据处理铁律

凡是处理超过 100 个文件或预计耗时超过 5 分钟的任务，强制执行两步流程：

**第一步：点火测试**
- 先拿 3~5 个文件跑脚本，确认语法正确、输出格式符合预期。
- 检查是否有 NaN/Inf、shape 错误、字段缺失等。
- 任何时候不得跳过这一步直接全量跑。

**第二步：全量执行**
- 点火测试通过后才可全量跑。
- 全量跑时必须输出进度（每 N 个文件报一次），输出写入日志文件方便随时查看。
- 全量跑完后必须校验结果完整性（数量是否对、有无遗漏）。

这步不是为了证明正确，是为了不浪费所有人的时间等一个语法错误的脚本。

## 当前路线探针输出（铁律，2026-06-13 起强制执行）

**每 epoch 必须产出两张合并探针图**，分别放入 `02_train/probes/train/` 和 `02_train/probes/val/`：

```
02_train/probes/
├── train/
│   ├── train_epoch001_y16.png
│   └── ...
└── val/
    ├── val_epoch001_y16.png
    └── ...
```

- **格式**：3 行 × 3 列（carotid/muscle/phantom × baseline/pred/gt），一张图看清全貌
- **命名**：`{train|val}_epoch{NNN}_y{Y}.png`（epoch 三位数补零）
- **实现**：调用项目根目录的 `probe_utils.py` 中的 `generate_epoch_probes()`
- **频率**：**每 epoch**（不只在 snapshot_epochs），不套 if 条件
- **固定索引**：每类取第一个样本，整个训练期间不变

此外仍需产出：

- **stability.csv**：每 epoch 记录 loss、SSIM3D 值、L1 值（及其他 metric）
- **loss 曲线**：在 snapshot_epochs 时生成
- **summary.md**：报告 loss/SSIM 是否随 epoch 改善、pred 是否脱离 baseline

## 实验总结归档铁律（2026-06-13 起强制执行）

每个训练 run，无论是正常完成、红线停止、OOM、NaN/Inf，还是被人工中止，都必须在服务器实验目录内保留可直接翻看的总结文件。

- **必须有两份总结**：
  - `02_train/summary.md`：训练阶段产出的正式总结
  - `summary.md`：复制到 run 根目录，方便打开实验文件夹第一眼看到
- **中断也要总结**：如果 notebook 因红线或异常提前停止，必须手动补写/复制总结，写明停止 epoch、停止原因、已生成与缺失的产物
- **总结只报事实数字**：loss/SSIM/L1、pred_std、train vs val、对抗健康度、SNR/FFT/BN 趋势、checkpoint/probe 完整性；不做影像质量结论
- **不得只把总结留在聊天记录里**：聊天窗口不是实验记录，服务器 run 目录才是归档来源
- **交付前检查**：最终回复用户前，必须确认服务器上 `summary.md` 与 `02_train/summary.md` 均存在

> 旧 Phase 2a 的复数探针和 per-category 单独 triplet 图已废弃。`save_triplet_figures` 不再使用，被合并探针替代。

## notebook 规范

- **强制 notebook 格式**：train.ipynb，8 个 Cell 贯穿到底
- 三段式新 run：旧 run 不动，每次新跑独立目录
- 不分叉三件套：ipynb + 数据 + 产出 一一对应
- Cell 1 自检：打印关键参数/path/shape，确认环境正确
- Restart & Run All：确保从头可复现
