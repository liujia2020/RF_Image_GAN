## 最近两周发生了什么（2026-06-05 ~ 06-08）

1. **坏 cache 发现**：诊断确认旧 fp16 cache 在 NTFS 盘满时写入静默失败（idx=0 NaN, idx=700 全零），原始 H5 完好。
2. **全盘重组**：四盘重新分区格式化，管线数据统一按 patch 尺寸组织（`rf_pipeline/64x32x32/`）。
3. **fp16 溢出诊断**：全量 1500 扫描发现 label 192/1500、baseline 377/1500 溢出。根因：normalize=False，scale 只存不用。
4. **scale 修复**：normalize=True，三字段同除 scale。Codex 改两端代码，Proma 独立交叉验证通过。
5. **文档体系重构**：统一模板（来源→目的→方法→流程→⚠️踩坑），三方文档分类（原则/Claude/Codex/笔记）。
6. **struct 归一化**：Phase2a v0 发现 struct:adv=43,000:1 量纲失衡。实现 label_mean_envelope 归一化（s = mean(|env(label)|) + 1e-8），数学上 struct_new = struct_old/s。Proma 独立验证确认等价性（max rel_diff 1.08e-7）。
7. **Phase 2a normstruct v1 训练完成**：50 epoch 零 NaN，struct→O(1)。但 carrier（lambda=0.5）未经归一化，占 G_total 99.9%。D_fake_score 从 epoch 3 起卡 0.500。pred_SNR 持续下降。
8. **实验目录重组**：去掉 runs/ 中间层，四段式（01_config/02_train/03_validate/04_proma_verify），Proma 验证脚本迁入 04。
9. **Phase 2a v2 关 carrier 消融实验**：lambda_carrier=0，只用 adv+struct。19 epoch 中止。struct:adv=1:1 比例完美但 G 几乎不学（G_struct 仅降 1.4%）。三实验横向对比展示因果链。
10. **v2 后续三方分析（Claude-Proma-用户）**：Claude 挑战 Proma 的初步结论——v2 只证明"当前坏判别器下 carrier 不可去掉"，不能证明 carrier 本身不可替代。核心病根可能是对抗机制三轮从未生效（D_fake 永远 0.50, D_real=0.73）。Proma 承认逻辑漏洞并接受 Claude 的修正。用户提出 log 压缩观察，引发讨论后确认：线性除标量归一化对复数数据比 log 压缩更合适，不需要整体换压缩空间。用户明确最终目标 B-mode（复数 RF 非必需）。三方收敛：carrier 归一化 + 三损失 1:1:0.25 + 判别器不动，建立干净基线让对抗问题无所遁形。
